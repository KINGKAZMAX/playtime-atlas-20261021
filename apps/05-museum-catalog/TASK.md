## 3. 目录条目要求

- 覆盖 **7 个时代**（与 06 的展厅数量对齐）：
  `origins` 1950–1969 · `arcade` 1970–1979 · `home8bit` 1980–1989 · `console16` 1990–1999 ·
  `online` 2000–2009 · `mobile` 2010–2014 · `modern` 2015–2026
- 每个时代同时覆盖**硬件**与**软件/作品**两类条目。
- 每条**必须**有：
  - `year`（首次公开/发布年）
  - `era`（上述受控词表之一）
  - `platform`（当时主要平台/载体）
  - `creator`（厂商或个人）
  - `summary`（一句事实描述，不含评价性夸张）
  - `significance`（为何值得进馆，一到两句）
  - `sourceUrls`（≥1 条；年代/平台/史实分别可追溯）
  - `imageLicense`（该条目配图的可用状态与许可）
- **不宣称穷尽**全时代：文档中显式写明为「代表性选样，非编年全集」。

## 4. 参考站比较要求

每个参考站记录 5 项：**URL / 截图参考 / 交互 / 美术 / 许可**。
- 截图参考需指向**真实可核验**的图像来源（官方图库/自有抓取快照/官方商店页），并标注抓取时间。
- 许可需注明：内容许可、图像许可、以及「可参考的机制/交互模式」与「不可复制的品牌视觉」边界。

## 5. 研究方法与证据纪律

1. 每条目录项的年代、平台、厂商先用**官方/馆方/一手**来源确认；百科类仅作交叉核对并记为次级源。
2. 所有抓取记录 URL 与访问时间；失效链接标注并替换。
3. 不使用未授权 ROM、商业游戏截帧、品牌 logo、商标字体作为交付素材。
4. 所有 `imageLicense` 字段明确三种状态之一：`public-domain` / `cc-by-sa-4.0` / `cc-by-4.0` / `cc-by-nc-*` / `permission-required` / `no-image`（不提供配图，仅文字与抽象程序化图形）。
5. 交付图像一律使用**程序化生成**的抽象图形（Canvas/SVG），不复用任何参考站原图。

## 6. 验收标准

1. `catalog.json` 条目数 ≥ 70，JSON 可解析，字段齐全且无空值（`imageLicense` 除外允许 `no-image`）。
2. 7 个时代均有条目，每个时代同时有硬件与作品条目。
3. 每条 `sourceUrls` ≥1 且可访问（抽样 ≥15 条验证 HTTP 200/3xx）。
4. `REFERENCE-DESIGN.md` 覆盖 ≥8 个**真实存在**站点，每站 5 项齐全。
5. `handoff/` 首批 20 条已交付 06 目录。
6. `manifest.json` 字段齐全，`status` 反映真实完成度。
7. `QA.md` 记录上述每项的实际检查方式与结果，不把缺失记为通过。
