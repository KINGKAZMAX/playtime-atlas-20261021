### 1.1 测试环境注意事项（影响验收脚本，不影响产物）

| 事项 | 处理方式 |
| --- | --- |
| 平滑滚动干扰点击稳定性检测 | 验收期间注入 `html{scroll-behavior:auto}`；**只作用于测试会话**，不改变产物 |
| 启动参数 | **不加 `--disable-gpu`**：该参数会让动画中的 canvas 无法合成进视口截图（元素截图仍正常） |
| 机器负载 | 本机同期有其它会话并发跑浏览器实例，系统负载一度达 90+，墙钟被严重拉长。验收脚本因此做了三处加固（见 1.2） |
| Chromium 被系统杀死 | 负载过高时会出现 `Target page, context or browser has been closed`；这是**宿主资源问题**，重跑即可 |

### 1.2 本轮对验收脚本本身做的加固（不削弱任何断言）

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 控制条按钮用位置型 CSS 选择器（`.btn:nth-child(4)`）定位，一旦在按钮之间插入元素就会点错按钮（本轮真实发生：把「存档」点成了「速度」） | 产品侧给控制条按钮加了稳定标识 `data-act="start|pause|speed|save|load|reset|mute"`；脚本改用 `[data-act=...]` 定位 |
| 2 | 「准备阶段 22 秒自动开波」与慢机器之间存在竞态：波次自行开始 → 灯塔被打穿 → 结算遮罩挡住后续点击 | 脚本用白盒接口在测试期把 `prepTimer` 拉长并维持灯塔耐久（**测试侧干预，不改变产品行为**）；开波断言改为「波次编号必须推进」而非固定值 |
| 3 | 截图取景时战场画布可能已滚出视口，产出「一片空白」的无效证据 | 每次截图前把对应画布 `scrollIntoViewIfNeeded()`；重生成全部 12 张验收截图并逐张目视复核 |
| 4 | 方向键用「按下→间隔→抬起」模拟轻点，间隔在慢机器上会被拉长到超过产品连发延迟，一次轻点被判成按住、光标连跳多格 | 产品侧把连发延迟从 0.24s 提到 0.40s（缺陷 16）；脚本侧改用 `keyboard.press()` 表达真实轻点 |

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | **「设施详情」面板每帧重建 DOM** | 升级 / 回收按钮在点击落点前被卸载，**按钮点不动** | 改为「内容变化才重建」：用 key 比对选中塔的 id/等级/索敌模式；升级按钮只改 `disabled`，不换节点；击毁数与资源条用独立节点增量更新 |
| 2 | **键盘从未产生「刚按下」事件** | `wasPressed()` 只对触屏生效，键盘的 `Z`/`X`/`Enter` 全部无效 | `Input.onKeyDown` 同步写入 `pressed` 集合；`setEnabled(false)` 时一并清空，避免切换展项后残留 |
| 3 | **展项根节点从未加 `is-active` 标记** | 两个展项自己的 keydown 处理器**始终提前返回**，键盘路径整体失效 | `setActive()` 同步切换 `is-active` class |
| 4 | **难度下拉框长期持有键盘焦点** | 选过一次难度后，数字键 / `Enter` / `U` 全被下拉框吃掉 | `change` 事件里 `diffSelect.blur()`，把焦点交还给游戏 |
| 5 | **掌机出生点落在门牌格上** | 玩家一进小镇就站在洞窟门上，按 `A` 立刻被弹进洞窟 | 出生点与各区域入口落点全部避开门牌格；新增「回到小镇时从对应门口出来」的落点表 |
| 6 | **轻点方向键可能完全无效** | 60Hz 轮询会漏掉「按下→抬起」快到不足一帧的轻点 | 光标改为「刚按下即移动 1 格」+ 0.24s 后 0.08s 间隔的自动重复；`Input` 新增 `heldFor()` |
| 7 | **建造失败无任何反馈** | 在航道 / 岩块 / 灯塔格上按 `Enter` 毫无反应，玩家会以为按键失灵 | 新增 `explainBuildFailure()`，按格子类型给出具体原因横幅 + 提示音 |
| 8 | **非当前展项仍在全速渲染** | 两个画布同时空转，拖慢页面、影响截图稳定性 | `setActive(false)` 直接 `loop.stop()`；头部装饰画改用 `IntersectionObserver`，滚出视口即停绘 |
| 9 | **每帧新建渐变对象** | 渲染层不必要的分配 | 背景 / 灯塔塔身渐变按 ctx 缓存 |
| 10 | **NPC 交互判定过严** | 必须精确站在相邻格才能对话，触屏几乎点不准 | 改为 1.6 格半径判定，机关 / 门 / 灯芯仍按「自身格 + 朝向格」判定 |
| 11 | **图例容器与真实来源角标同 class** | 统计角标数量时会误计 | 图例容器改用独立 class `srcdemo` |
| 12 | **「准备阶段自动开波」没有任何界面提示** | 准备阶段 22 秒后自动开波，「立即开波」按钮**静默变灰**，玩家会以为按钮坏了 | 控制条常驻状态提示（`.bar__countdown`）：「Ns 后自动开波」/「第 N 波进行中」/「本局已结束」 |
| 13 | **灰烬编队错用玩家波次时钟** | 在准备阶段（`inWave=false`）`waveClock` 不推进，AI 明明宣布「⚡ 突击已发动」，编队却**始终不出现在场上** | 新增灰烬航道独立时钟 `ashClock`：`stepDefense` 独立推进，AI 编队时间戳改用 `ashClock`，突击真正落地 |
| 14 | **控制条按钮缺少稳定标识** | 验收脚本只能用位置型 CSS 选择器定位按钮，DOM 一变就点错（本轮真实点错过一次） | 七个控制按钮补 `data-act` 属性，脚本按动作定位 |
| 15 | **NPC 对话的首句既无年份也无来源角标** | 史料角标只挂在对话的中段句上；玩家读到的**第一句**是纯氛围叙述，既无具体年份也无来源链接 | 三位 NPC 的开场白各补一句**带具体年份 + 来源角标**的史实（岑→Xbox Live 2002 / 岚→Steam 2003 / 薇→WoW 2001），沿用既有 `sourceChipEl` 组件与 65 条台账口径，不另造格式 |
| 16 | **方向键连发延迟过短（0.24s）** | 慢机器上「按下→抬起」间隔一旦超过连发延迟，一次轻点会被当成按住，光标连跳多格（实测跳到 (7,1)） | 连发延迟提到 **0.40s**（常规桌面 UI 量级）：轻点只移动 1 格，真正按住才持续移动 |
| 17 | **掌机 HUD 的 DOM 文字不达 4.5:1** | `--pocket-d4` (#9a6a74) 作正文在机身底 `#1a1424` 上仅 **4.01:1**、在 `#0d0912` 上仅 **4.40:1**；涉及上屏标签 / 状态栏「地点·体力·回声」/ 碎片计数 / 下屏标签 / 提示行 / 对话日志 / 系统键共 7 处 | 新增 `--pocket-text: #b8848e`（d4 的**提亮同色相**版本：d1 5.75:1 / d2 4.65:1 / ink 6.32:1 / sysbtn 5.27:1），7 处 DOM 文字改用之；**机身色阶与画布点阵色板（`palette.ts` 的 `d4`）一律不动**（§4.2 边界判定第 2 条） |
| 18 | **来源角标触摸目标仅 20px 高** | `.src` 是可点击外链（全站 104 处），`line-height: 18px` + 上下各 1px 描边 = **20px**，低于 §5.1 的 24px 硬底线（AA 2.5.8） | `.src` 改 `line-height: 23px` + `min-height: 25px` → 实测 43×25（留 1px 余量，避免高分屏/非整数缩放下的亚像素下溢，如 23.993px 被判不足）；台账密集列表版面无溢出、无破版 |

> 缺陷 12–14 是本轮**复跑验收**时新发现并修复的；此前 52 项断言虽全绿，但因机器负载导致验收脚本出现竞态，
> 才把「按钮静默变灰」「AI 宣布突击但单位不出场」这两个真实的体验/逻辑问题暴露出来。
