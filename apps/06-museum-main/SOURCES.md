# 来源 · SOURCES

> 本文件说明「回响电玩馆 / PLAYTIME ATLAS」的**史料来源方案与可核对路径**。
> 每一件展品的来源都写在展品数据本身的 `sourceUrls` / `sourceTitles` 字段里，
> 并在主站「展品详情 → 来源与核对」中逐条列出、可直接点开。

---

## 1. 逐条来源（条目级）

| 项 | 说明 |
|---|---|
| 存放位置 | `public/data/catalog.json`（来自 05-museum-research）与 `src/data/catalog.local.js`（本馆本地初版） |
| 字段 | `sourceUrls`（可点开的公开来源）、`sourceTitles`（来源名称）、`imageLicense`（图片与素材许可） |
| 数量 | 馆藏 211 件，登记来源 485 条 |
| 合并规则 | 05 的策展目录优先；本馆本地初版只补充外部未收录的条目；**按来源条目去重**（同一作品在两份目录中 id 不同但指向同一来源时只陈列一次） |

### 来源类型

- **公开百科条目**（主要）：每件展品至少一条，指向该作品或硬件的公开条目。
- **多来源条目**：部分展品登记了两条以上（如街机时代作品同时给出作品条目与机型条目）。
- **待补**：本地初版中个别条目在 05 交付后已被同来源的正式条目覆盖，链接随之升级。

## 2. 来源可解析性校验（机器可验证）

```bash
npm run verify:catalog          # 联网逐条查询，确认每个来源条目都能解析
node scripts/verify-catalog.mjs --offline   # 只跑结构校验，不联网
```

脚本行为：

1. **结构校验**：必填字段、id 唯一、年代存在、来源非空、许可字段齐全、
   年份落在所属年代区间内、每个年代都有展品、年代数 ≥ 7。
2. **来源校验**：把每个来源 URL 里的百科条目标题提交给公开 API，
   逐条确认条目可解析（自动处理重定向与标题规范化）。

**诚实性约定**：若网络不可达导致部分条目未能校验，脚本会明确报告
「来源校验未完成（N 个批次请求失败），不能声称『全部可解析』」并以**非零码退出**，
不会把未校验的条目算作通过。

> 限流说明：公开百科 API 对高频请求会返回 429/403。脚本采用
> 「每次一个标题 + 固定间隔 + 指数退避」策略（`scripts/lib/net.mjs`），
> 并优先使用 `curl` 以兼容本机代理环境（Node 内置 fetch 默认不读 `https_proxy`）。

## 3. 馆方叙述与来源的关系

- **馆方叙述为本项目原创改写**（`summary` / `significance`），不是来源原文的翻译或摘抄。
- 两者在数据里分字段保存，在界面上分区呈现：叙述区是馆方文字，来源区是可点开的核对入口。
- 遇有分歧，以来源原文为准。

## 4. 馆方立场与参考边界

本馆**参考了公开电子游戏博物馆 / 时间线站点在「时间线、检索、展签、可玩入口」上的通行做法**
（具体站点对比与设计分析由 05-museum-research 在 `REFERENCE-DESIGN.md` 中记录），
但以下内容均为本项目独立完成，不复制任何既有展陈：

- 作品名「回响电玩馆 / PLAYTIME ATLAS」、英文名与徽标；
- 全部界面文案、年代叙述、展品叙述与史实意义；
- 视觉方案（深墨蓝 + 暖纸白 + 信号橙）与年代辅色体系；
- 版式与交互（时间长廊门、展签版式、展柜分区、2D 无障碍目录、3D 展厅动线）；
- 全部图形资产（程序化生成的原创 SVG 与 3D 体块）；
- 字体选择与排版方案。

**不包含**：任何未授权 ROM、商业游戏美术或音频、品牌 logo、真实产品外形的复刻。
展品中出现的作品名与厂商名仅用于史实指涉，权利归各自权利人所有。

## 7. 覆盖范围的诚实声明

本馆覆盖 1950 年代早期电子实验到 2020 年代云端与新形态，划分为十个年代展厅，
收录 211 件代表性展品。这是**代表性样本**，不是穷尽性目录：

- 早期的收录密度高于近年；
- 年代划分是本馆为叙事清晰所做的编辑判断，并非唯一标准切法；
- 2020 年之后的条目仍在持续补充中。

不虚称覆盖全部作品，也不把「代表性」表述为「完整」。
