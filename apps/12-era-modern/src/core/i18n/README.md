# 文案骨架（i18n skeleton）

> 状态：**骨架已就绪，尚未切换语言。**
> 页面默认仍为中文，界面里**没有**语言切换入口——这是刻意保留的一步。

---

## 1. 这份骨架解决什么问题

改版派单要求「准备 zh/en 文案 key 骨架（先不切语言）」。
本目录现在的文案全部**硬编码在 JS 里**（`el('button', {}, '开始')` 这种形式），
一旦将来要出英文版，就得逐个翻文件替换，既容易漏，也无法做对等校验。

骨架把这些文案收拢成一张**点分键名表**：

```
<域>.<子域>.<键>
域：brand / nav / title / common / footer / settings / hall / pulse / atrium / halo
```

共 **162 个键**，zh / en 键集合完全一致（由 `scripts/check-i18n.mjs` 强制校验）。

## 2. 文件

| 文件 | 作用 |
|---|---|
| `zh.js` | **中文的权威来源**，与页面现有文案逐字一致 |
| `en.js` | 英文译文，键集合与 `zh.js` 严格一致 |
| `index.js` | 取用入口：`t(key, vars)` / `getLang()` / `setLang()` / `onLangChange()` / `allKeys()` |

## 3. 取用方式

```js
import { t } from '../core/i18n/index.js';

el('button.btn', {}, t('settings.open'));
el('p', {}, t('pulse.setup.best', { score: 1200 }));   // {name} 占位
```

回落规则：`当前语言 → zh → 键名`。任何情况下都不会返回 `undefined` 或空白。

## 4. 覆盖范围（重要）

### ✅ 已入骨架：界面骨架文案

| 域 | 内容 |
|---|---|
| `brand` / `nav` / `title` | 品牌、导航项、页面标题 |
| `common` | 返回展厅等通用动作 |
| `footer` | 页脚三段声明 |
| `settings` | 设置面板：标题、说明、4 个开关、判定校准、3 个按钮、toast 文案 |
| `hall` | 展厅主站：主视觉文案、5 个章节标题与副标题、CTA、展项入口、三条声明 |
| `pulse` | 节奏展项：模式名、选单标题、HUD 标签、按钮、暂停遮罩、结算面板、提示语 |
| `atrium` | 解谜展项：HUD 标签、4 个按钮、图例、操作提示、结算面板、toast 文案 |
| `halo` | 观景台：声明、设备支持表、检测按钮、面板脚注 |

### ❌ 未入骨架：内容型文案（有意为之）

| 内容 | 为什么不入骨架 |
|---|---|
| 展项长描述（`src/data/hall.js` 的 `desc` / `note`） | 属于**作品内容**而非界面文案，随展项迭代变化；纳入骨架会让「改版」和「内容更新」耦合 |
| 时间轴 24 条史料（`src/data/timeline.js`） | 同上；且每条都带一手来源链接，翻译需与史料校对一起做 |
| 关卡名称与叙事（`src/data/levels.js`） | 同上 |
| 谱面描述（`src/data/charts.js`） | 同上 |
| 热点长文（`src/vr/halo.js` 的 `HOTSPOTS`） | 同上；6 条展签均为引自一手来源的正文，翻译需标注原文 |
| 作品名（脉冲走廊 / PULSE CORRIDOR 等） | 既有设计就是**中英并置**，不是可切换文案 |

> 若将来决定做完整英文版，这些内容需要单独一轮「内容型文案」工程：
> 建表 → 翻译 → 术语统一 → 史料校对 → 与史料链接的对应关系核验。

## 5. 当前接线范围

**只有 `src/ui/shell.js` 接了 `t()`**（导航 / 品牌 / 页脚 / 设置面板）。
三个展项页与展厅主站仍用硬编码文案——它们对应的键**已经在表里**，
迁移是逐文件替换 `el(..., '字面量')` → `el(..., t('键名'))` 的机械工作，可分批做。

这样安排的理由：先让骨架与校验器跑起来、让 `t()` 有真实调用点，
再逐步迁移；避免一次性改动 6 个视图带来的回归风险。

## 6. 怎么打开语言切换（下一步，尚未实施）

1. 迁移剩余视图到 `t()`（见 §5）。
2. 在 `src/ui/shell.js` 的设置面板加一个语言开关，写入 `src/core/settings.js`。
3. `setLang()` 已实现：会同步 `<html lang>`（`zh-CN` / `en`）并通知订阅者。
4. 订阅者在语言变化时**重新渲染**当前视图（各视图的 `mount*` 函数需要可重入）。
5. `src/core/i18n/index.js` 的 `onLangChange()` 已预留。

## 7. 守门

```bash
node scripts/check-i18n.mjs
```

校验三件事：

1. zh / en 键集合完全一致（缺一边即失败）；
2. 没有空文案；
3. 同一键在两种语言里的 `{name}` 占位符一致（防止译文漏掉变量）。

改动 `src/core/i18n/*.js` 后必须重跑。
