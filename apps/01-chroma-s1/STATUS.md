## 3. 关键决策记录

| 决策 | 理由 |
|---|---|
| 选 @nutlope 的落地页作为参考作品 | 本次可核验的 5 个 M3.1 Flash 网页类作品里互动量最高（1,417 赞 / 13 万播放），模型证据是作者原帖自述，产物形态是标准落地页，适合完整复刻工艺 |
| **不做像素级复刻，改做原创改编** | MASTER-UPDATE.md 明确要求重设作品名/文案/字体/配色/布局/形态。本作品另立虚构产品「CHROMA S1」，只保留「同等工艺水准」这层参照 |
| 选光谱色度仪而不是游戏机 | 参考作品是手持游戏机；换成品完全不同的测量仪器可避免形态层面的复制，同时光谱计算天然适配「可交互实验室」这一核心交互 |
| 深色仪表盘配色 + 宽体等宽字体 | 参考作品是米白纸底 + 糖果色 + 窄体粗无衬线；反向选择可读性更好的仪器风，且在视觉上明显区隔 |
| 色彩计算自己实现，不调用外部色库 | 页面核心主张是「把颜色量出来」，读数必须是真算出来的；CIE 1931 配色函数与 CIEDE2000 全部自行实现，无第三方色度依赖 |
| 用 `RoomEnvironment` 而不是 HDR 文件 | three 自带的程序化房间环境，无需外部贴图即可让金属材质正确出图，符合「资源本地化」 |
| 加 `?motion=off` 模式 | 在动画时间轴不推进的环境（后台标签、被节流的渲染器、截图流水线）里，入场动画会把内容卡在起始态。提供显式静态模式，保证任何环境下内容都可见 |
| 用 Playwright 驱动本机 Chrome 做验证 | 会话内置浏览器的渲染时间轴会被冻结（rAF 停摆），无法观察动画与三维连续帧；改用本地 Chrome 做真实点击与截图，`?motion=off` 模式同时也在内置浏览器里做过点击核对 |

## 4. 已发现并修复的问题

完整记录见 `QA.md` 第 4 节。要点：

1. `controls.update()` 与 `change` 事件互相触发 → 无限递归爆栈（已加重入保护）。
2. 光谱基准曲线在模块初始化时取了一次就再没更新 → 换样本后曲线与 ΔE00 全部错（已改为随目标色重算）。
3. `spectrumToRgb` 误把 XYZ 当成 L\*a\*b\* 做逆变换 → 颜色全错（已改为 XYZ→线性 sRGB 矩阵）。
4. 噪声按绝对量叠加 → 暗色样本被噪声淹没，ΔE00 冲到 47.78（已改为随响应峰值缩放的相对噪声）。
5. 金属材质缺环境贴图 → 三维机身发黑（已加 `RoomEnvironment` + PMREM）。
6. 入场动画的终态依赖动画时间轴 → 在被节流的环境里标题与画布永久不可见（已改为「默认可见 + 时间轴可用时才播动画」）。
